* pi-coding-agent layer

This layer installs and configures the official
[[https://github.com/dnouri/pi-coding-agent][pi-coding-agent]] Emacs frontend
(MELPA) for the [[https://pi.dev][pi coding agent]]. It provides a two-window
interface for AI-assisted coding: a chat buffer with rendered markdown and a
separate prompt composition buffer, backed by a =pi --mode rpc= subprocess.

** Prerequisites

- Emacs 29.1 or later with tree-sitter support
- pi coding agent =@earendil-works/pi-coding-agent= 0.81.0 or later,
  installed and in PATH, e.g.:

#+begin_src sh
npm install -g @earendil-works/pi-coding-agent
#+end_src

The layer adds =~/.local/bin=, =~/bin= and =/usr/local/bin= to
=exec-path= if they contain the =pi= binary, so GUI-launched Emacs
finds it even without the interactive shell's PATH.

Tree-sitter grammars for markdown are installed automatically on first
session start (or manually via =pi-coding-agent-install-grammars=).

** What it does

- Declares the =pi-coding-agent= package (its dependencies =transient=,
  =md-ts-mode= and =markdown-table-wrap= are pulled in by package.el).
- Keeps the package's own behavior: sessions are per-project (one
  process per directory, optionally named for parallel sessions),
  Evil keybindings load automatically when Evil is present, and the
  built-in =C-c= bindings in chat/input buffers are unchanged.
- Adds Spacemacs leader keybindings (see below).
- Sets =pi-coding-agent-project-trust-policy= to =approve=, so
  project-local =.pi= prompts, skills, settings, themes, and
  extensions are available in RPC mode (which has no interactive
  trust prompt).
- Requires the =spacemacs-layouts= layer (persp-mode): each opened pi
  session is a perspective (a workspace with its own buffer set).
- Adds session management: a global session list, new-session with
  directory prompt, and close-session (see below).

** Session management

Every opened pi session is a persp-mode perspective — "like a project":
the buffers you open while in the session (files, terminals, pi
chat/input) belong to that perspective, and =SPC b b= only shows the
current perspective's buffers plus common buffers (=*scratch*=,
=*Messages*=; see the optional =my-persp= layer below).  =SPC b B=
shows all buffers.

- =SPC a i i= (=pi-coding-agent/switch-session=) — list all pi
  sessions (the current one is excluded): opened ones (marked ●) first,
  then closed.  Each candidate
  shows the session title (name or first message), directory, message
  count, and age.  Selecting a closed session opens it: a new
  perspective is created, the pi process is started, the session file
  is resumed, and the previously remembered workspace buffers are
  restored.  Selecting an opened session switches to its perspective
  (reviving a dead pi process).  Sort orders are configurable:
  =pi-coding-agent/session-sort-opened= (default =alpha=) and
  =pi-coding-agent/session-sort-closed= (default =chrono=).
- =SPC a i n= (=pi-coding-agent/start-new-session=) — start a brand
  new session: always prompts for the directory (the default follows
  the layout's directory logic — terminal cwd, session dir inside pi
  buffers, buffer dir elsewhere).  Refuses when the directory already
  has a live unnamed session (use =SPC a i S= for parallel named
  sessions).
- =SPC a i d= (=pi-coding-agent/close-session=) — close the current
  session: stops the pi process, kills the perspective's buffers
  (standard unsaved-change prompts; common buffers and buffers shared
  with other perspectives are spared), and removes the perspective.
  The workspace is remembered, so reopening the session from the list
  restores its buffers.
- =SPC a i N= — reset the current session (=pi-coding-agent-new-session=,
  moved from =n=).

Perspectives are named =«title» · «abbrev-path»= (e.g. =Refactor auth ·
~/.emacs.d=); the title follows the session =/name=, else the first
message, else =New session= until the first prompt.  Renaming the
session (package command or =/name=) updates the perspective label;
renaming the perspective yourself (=SPC l r=) locks the label.

** Session restore after restart

Pi processes die with Emacs; what comes back after a restart depends
on =dotspacemacs-auto-resume-layouts=:

- =nil= (default): all sessions are closed after a restart.  Use
  =SPC a i i= to reopen them — the registry restores each session's
  workspace buffers.
- =t=: persp-mode restores every perspective with its buffers at
  startup — files (persp defaults), terminals (if the =my-persp= layer
  is enabled), and the pi session itself (chat/input buffers are
  re-opened and the session file resumed).  Caveat: N sessions mean N
  pi processes spawning at startup.

Session metadata (perspective ↔ session file mapping, captured buffer
specs) is stored in the registry file under
=spacemacs-cache-directory= =/pi-coding-agent/registry.el= (runtime
state, not dotfiles).  The registry fails open: if it is missing or
corrupt, sessions still list and open from the JSONL files — only the
workspace-buffer memory is lost.

** Optional: the =my-persp= layer

A small private layer (=private/my-persp=, listed before
=pi-coding-agent=) that enhances persp-mode generically, with zero
coupling to this layer:

- Common buffers (=*scratch*=, =*Messages*=; configurable via
  =my-persp-common-buffer-regexps=) are injected into every
  perspective, so they stay reachable from =SPC b b= in any layout.
- Terminal buffers (vterm, term, eshell, shell) are saved to persp
  state with their real working directory (vterm via
  =/proc/<pid>/cwd=) and relaunched there on restore.

Without =my-persp= the pi layer still works end to end; only terminals
are not restored across restarts, and common buffers are not visible
inside session perspectives.

** Usage

- =SPC a i i= — list all sessions: open the chosen one or switch to it
- =SPC a i p= — start or focus the pi session for the current project
- =SPC a i n= — start a new session (asks for the directory)
- =SPC a i d= — close the current session (and its workspace)
- =SPC a i l= — apply the saved window layout (start/focus a session)
- =SPC a i t= — hide/show the pi windows
- =SPC a i m= — full transient menu (model, thinking level, sessions, …)
- =SPC a i S= — start a named (parallel) session
- =SPC a i N= — reset / new session in the current directory

** Window layout

The layer ships a purpose window layout (=pi-coding-agent.window-layout=,
loadable with =SPC a i l=):

#+begin_example
+-------------------------+-------------------------+
| pi-coding-agent-chat    |                         |
| (70% height)            | any                     |
+-------------------------+ buffer                 |
| pi-coding-agent-input   |                         |
| (30% height)            |                         |
+-------------------------+-------------------------+
#+end_example

The left column (chat + input) takes =pi-coding-agent/layout-width-ratio=
of the frame width (default =0.5=); the right =edit= pane takes the rest.
=pi-coding-agent/layout= builds the layout from that variable at apply
time, so changing it takes effect on the next =SPC a i l=.

- The chat and input buffers have dedicated purposes (=pi-chat= /
  =pi-input=) mapped from the package's modes in =config.el=, so they
  are always routed to the left panes.
- The right pane uses the =edit= purpose and is not dedicated, so it
  can hold any buffer — and since file-visiting buffers classify as
  =edit=, the fill loop fills it with an existing buffer instead of
  creating a dummy.  =pi-coding-agent/layout= restores the buffer you
  were in before the command to that pane; when the command is run
  from a pi buffer, it shows the most recently used non-pi buffer
  instead (and drops window-purpose's dummy placeholders).
- The layer directory is registered in =purpose-layout-dirs=, so the
  static default layout (=pi-coding-agent.window-layout=, kept in sync
  with the variable's default) is also available via
  =M-x purpose-load-window-layout=.
- =pi-coding-agent/layout= refreshes the purpose tables first and
  re-asserts the session buffers in their panes, so it works even
  after layer reloads (=SPC f e R=) that leave purpose-mode's compiled
  tables stale.
- =pi-coding-agent/layout= never starts a new pi process when a
  session already exists: it reuses the current directory's session,
  falling back to the most recently used live session.  Only when no
  session exists at all does it start one, choosing the directory as
  follows:
  - inside pi chat/input buffers, the session's recorded directory is
    reused (this also revives a session whose process died);
  - inside a terminal buffer (vterm, ansi-term/term incl. multi-term,
    eshell, shell-mode), the terminal's current working directory is
    used — term-mode via `term-command-hook', shell-mode via dirtrack
    and eshell natively keep `default-directory' in sync with the
    shell's cwd; vterm only updates it from OSC 7 (which plain zsh
    never emits), so its real cwd is read from the process's
    `/proc/<pid>/cwd' symlink instead.  When the real cwd cannot be
    determined (unreadable `/proc', dead terminal process), the user
    is prompted for the directory with `default-directory' as the
    default instead of silently using a possibly-stale value;
  - anywhere else, the user is prompted for the directory, defaulting
    to the current buffer's directory (the visited file's directory,
    or `default-directory').  Cancelling the prompt aborts the command.

Inside a pi buffer:

- =C-c C-c= — send prompt (queues as follow-up if busy)
- =C-c C-s= — queue steering (interrupts after current tool)
- =C-c C-p= — open the transient menu
- =C-c C-r= — resume a session
- =C-c C-k= — abort current operation
- =TAB= / =@= — path completion / file references in the input buffer

** Configuration

Package options are set in the =init= function in =packages.el=:

- =pi-coding-agent-evil-integration= — load Evil keybindings (default =t=)
- =pi-coding-agent-project-trust-policy= — =approve= (default) /
  =default= / =no-approve=
- =pi-coding-agent-input-window-height= — height of the input window
  (set it in =config.el= or via =M-x customize-group pi-coding-agent=)

Layer option (defined in =config.el=):

- =pi-coding-agent/layout-width-ratio= — fraction of the frame width
  taken by the pi left column (chat + input), default =0.5=.  Set it
  in =dotspacemacs/user-config=, e.g.
  #+begin_src emacs-lisp
  (setq pi-coding-agent/layout-width-ratio 0.4)
  #+end_src
  or via =M-x customize-group pi-coding-agent=, then re-apply with
  =SPC a i l=.
